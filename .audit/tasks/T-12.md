# Task T-12: Fault Injection & Red-Team Resilience Audit (F-01 s/d F-13)

## Tujuan
Melakukan audit keamanan dan ketahanan (fault injection) independen oleh peran Red-Team pada FlashVeditor. Memastikan sistem menangani kegagalan koneksi, respons HTTP error dari gateway AI (401, 429, 500), respons malformed/truncated JSON, serangan CSRF bad origin, eksploitasi path traversal pada web endpoint, pencegahan kebocoran secret pada log, serta integritas path yang dilindungi (`protected paths`).

## Ruang Lingkup
- Test script: `.audit/tasks/test_T12_redteam_faults.py`
- Evidence log: `.audit/evidence/T-12/redteam-evidence.txt`
- Verdict: `.audit/rounds/T-12/r1/redteam.yaml`
- Matriks Pengujian: F-01 s/d F-13 (13 skenario kegagalan & keamanan)

## Rincian Kasus Uji (F-01 s/d F-13)
1. **F-01: Gateway Connection Refused (Network Down)**
   - Menstimulasikan gateway 9Router down / port tidak aktif.
   - Verifikasi: ditangani bersih via `SystemExit` ("Gemini unreachable"), tidak terjadi crash / unhandled exception, nol kebocoran secret.
2. **F-02: Gateway Connection Timeout**
   - Menstimulasikan socket / read timeout saat pemanggilan gateway.
   - Verifikasi: ditangkap dengan aman via `SystemExit` ("The read operation timed out"), proses tidak hang tanpa batas waktu, nol kebocoran secret.
3. **F-03: Gateway HTTP 401 Unauthorized / Invalid Key**
   - Menstimulasikan respons HTTP 401 saat kunci/token ditolak atau kedaluwarsa.
   - Verifikasi: dihentikan bersih dengan panduan perbaikan token yang jelas, kredensial tidak dicetak ke stderr/stdout.
4. **F-04: Gateway HTTP 429 Rate Limit Exceeded**
   - Menstimulasikan penolakan akibat batas kuota request terlampaui.
   - Verifikasi: mekanisme backoff retry dijalankan hingga batas, lalu keluar dengan pesan penanganan kuota, nol traceback tidak tertangani.
5. **F-05: Gateway HTTP 500 Internal Server Error**
   - Menstimulasikan respons gateway internal server error / crash.
   - Verifikasi: ditangani bersih dengan pesan status error gateway tanpa membocorkan trace internal aplikasi atau token.
6. **F-06: Gateway HTTP 404 Model Not Found & Fallback**
   - Menstimulasikan model pertama tidak tersedia pada kunci/gateway.
   - Verifikasi: sistem otomatis melakukan fallback berurutan ke model berikutnya dalam `MODELS` tanpa interupsi kegagalan prematur.
7. **F-07: Malformed / Truncated JSON Tolerance**
   - Menstimulasikan respons JSON yang terpotong atau rusak.
   - Verifikasi: `tolerant_json_parse` memulihkan data melalui parser baris key-value jika memungkinkan; kegagalan fatal yang tidak terpulihkan memicu `JSONDecodeError` secara terkendali tanpa state korup.
8. **F-08: Non-JSON / HTML Error Page on HTTP 200**
   - Menstimulasikan proxy / captive portal mengembalikan halaman HTML dengan status HTTP 200.
   - Verifikasi: parser menolak respons HTML dan memicu `JSONDecodeError` terkendali, mencegah korupsi format style.
9. **F-09: Markdown-wrapped Codeblock JSON (` ```json `)**
   - Menstimulasikan LLM mengembalikan JSON terbungkus blok markdown dan teks pembuka/penutup.
   - Verifikasi: kode pagar markdown otomatis dibersihkan dan isi JSON berhasil diekstrak dengan akurasi 100%.
10. **F-10: Cross-Site Request Forgery (CSRF) Untrusted Origin**
    - Mengirimkan request POST ke server review lokal dengan header `Origin` dari domain penyerang eksternal maupun origin palsu.
    - Verifikasi: server web secara ketat menolak request dengan status HTTP 403 Forbidden.
11. **F-11: Path Traversal Sanitization Defense**
    - Mengirimkan vektor path traversal (`..%2F..%2Fetc%2Fpasswd`, `/frames/../../etc/shadow`, dll.) ke endpoint review server.
    - Verifikasi: sanitasi path (`Path(...).name` dan validasi batas direktori) memblokir pelarian direktori dan mengembalikan HTTP 404/403. File sistem terlindungi.
12. **F-12: Secret Leakage & Credential Masking Audit**
    - Menguji pemanggilan error dengan simulated secret credentials; memindai seluruh log audit.
    - Verifikasi: seluruh secret tersanitasi menjadi `[REDACTED]`, tidak ada API key atau bearer token riil yang bocor ke output log atau Git repository.
13. **F-13: Protected Paths & Guard Integrity**
    - Menguji skrip pengaman `.audit/guard.py` terhadap target path terlindungi (`tests/`, `.audit/contract.md`, `.audit/protected-paths.txt`, `.audit/guard.py`, `.claude/agents/`).
    - Verifikasi: guard mengembalikan kode exit 2 (BLOCKED) pada path terlindungi dan kode exit 0 pada path yang diizinkan; status Git mengonfirmasi path terlindungi 100% utuh tanpa modifikasi.

## Kriteria Sukses
1. 13 skenario fault injection (F-01 s/d F-13) berstatus PASS 100%.
2. Tidak ada unhandled exception, uncaught tracebacks, atau silent data fallback ke provider eksternal.
3. Nol secret/kunci API riil yang terekspos di log bukti atau file audit (seluruh token menggunakan `[REDACTED]`).
4. Integritas protected paths diverifikasi dan tidak disentuh.
